# 번역 프로젝트 개선 구현 계획

## 목적

이 계획은 일본어 자막을 한국어로 복원·번역하는 현재 파이프라인을, 더 적은 사람 검수로도 근거를 추적하고 품질을 측정할 수 있는 작업 체계로 발전시키기 위한 실행 문서다. 목표는 자동 번역을 곧바로 신뢰하는 것이 아니라, 오류 위험이 큰 구간에 사람의 판단과 증거를 집중하고 그 결과를 다음 작업에 재사용 가능하게 만드는 것이다.

## 비목표

- ASR 점수, 위험 점수, 다수결을 의미의 자동 확정기로 만들지 않는다.
- 화면에 보이는 정보만으로 발화에 없는 의미를 추가하지 않는다.
- 기존 한국어 자막을 정답이나 자동 학습 데이터로 승격하지 않는다.
- P1/P2 검토만으로 작품 전체 품질이나 개선을 주장하지 않는다.
- 별도 승인 없이 외부 번역 서비스 또는 추가 모델에 원문을 전송하지 않는다.
- 이 문서는 일정·인력·비용을 추정하지 않는다.

## 현재 상태: 이미 구현된 보호장치

다음은 신규 과제가 아니라 현재 코드와 문서에서 확인된 기반이다.

- `inspect`는 입력 역할 후보를 찾고, 같은 역할 후보가 여러 개면 자동 선택하지 않으며, 입력 해시·SRT 구조 정보를 매니페스트에 기록한다.
- 구조 기준 SRT의 블록 번호·타임코드·순서를 잠그고, 기존 한국어 자막은 시간 겹침 기준의 후보로만 취급한다.
- `structure_fallback` 위험 큐는 긴 문장·질문·부정·행동 표현 등을 검토 우선순위로만 사용한다. 자동 오역 판정은 하지 않는다.
- P1/P2 장면 클립과 Whisper 후보를 만들 수 있으며, 같은 Whisper 계열의 여러 패스는 독립 근거가 아니라고 기록한다.
- 번역 결정에는 원문 충실본·감상용 자연본·근거·확신도·불확실성을 남길 수 있고, `apply-translations --strict`는 빈 값·일본어 잔존·기존 자막 단순 복사·구조 불일치를 막는다.
- `final` 패키징은 전체 블록 검수, 직접 청취, 근거·QA, 의미 프레임·가설 원장 및 평가 근거를 요구한다.
- 한국어 의미번역 경로의 허용 모델은 `gpt-5.6-terra` 하나로 고정되어 있다. 번역 큐, 결정 JSONL, 적용 보고서에 모델명이 남고, ASR·Subtitle Forensics·과거 외부 기계번역 초안에는 적용하지 않는다.

## 구현 진행 기록 (2026-07-26)

- **1단계 시간축 게이트: 부분 구현·코드 검증 완료.** `validate-timeline`은 ffprobe로 미디어 길이를 읽고 구조 SRT의 마지막 종료 시각이 범위 안에 드는지를 SHA-256과 함께 기록한다. `prepare-audio`는 통과 보고서 없이는 중단한다. 이 검사는 클립 범위 안전성만 검증하며 동일 편집본·오프셋·드리프트를 확정하지 않는다.
- **2단계 Terra 템플릿: 구현·계약 검증 완료.** `prompts/terra-semantic-translation-v1.*`에 버전·해시·출력 계약과 정상/근거 누락/근거 충돌/파일 누락 시험 사례를 고정했고, `validate-prompt-contract`가 이를 검사한다. 실제 모델 호출이나 품질 개선 주장은 포함하지 않는다.
- **3단계 평가 기반: 부분 구현·코드 검증 완료.** `init-gold-record`은 직접 청취·2인 전사·조정·허용/금지 해석을 기록할 미완성 템플릿을 만들며, `validate-gold-record`는 직접 청취 없이 `adjudicated` 상태를 통과시키지 않는다. `build-blind-review-pack`은 출처를 숨긴 로컬 A/B ZIP과 분리된 내부 키를 만든다. 실제 골드 답안·사람 블라인드 판정은 아직 없다.
- **4단계 근거 기반 검수: 구현·코드 검증 완료.** `build-review-pack`은 로컬 HTML, ASR·일본어 문맥·기존 후보·오디오 참조와 사람 작성 결정 템플릿을 한 패킷으로 묶는다. HTML은 외부 리소스를 사용하지 않으며 자동 의미 판정을 하지 않는다.
- **5단계 무작위 감사: 구현·코드 검증 완료.** `sample-audit`은 시드·추출률·계층·포함 확률을 기록하고, `summarize-audit`은 미검수 표본에서 recall/precision을 주장하지 않는다.
- **6단계 승인 용어집: 구현·코드 검증 완료.** `init-terminology`, `validate-terminology`, `terminology-conflicts`는 근거·범위·승인자 없는 전역 자동 치환을 막고 충돌을 사람 검토로 남긴다.
- **7단계 근거 그래프와 재현 실행 기록: 구현·코드 검증 완료.** `build-evidence-graph`은 블록·근거·결정·프레임·가설을 JSONL로 연결하고 고아 참조를 보고한다. `create-run-manifest`는 입력·프롬프트·산출물 해시와 작업 트리 상태를 보존한다.
- **8단계 Sol 반증: 실행 환경 미제공.** 현재 환경에는 `gpt-5.6-sol` 호출 경로가 없어 실제 독립 반증 실험을 실행하거나 결과를 만들 수 없다. Terra를 Sol로 가장하거나 자동 심판으로 대체하지 않는다.
- **실제 평가·최종 승격: 미완료.** 골드 답안, 사람 블라인드 판정, P3/P4 감사 판정이 아직 없어 `evaluation-validated`와 `final`은 차단된다. 패키징은 이제 완료된 사람 블라인드 검수 요약과 패킷을 요구한다.

## 확인된 현재 한계

- `inspect`는 SRT 구조와 기존 한국어 자막의 시간 겹침은 기록하지만, 오디오·영상 길이와 SRT의 최종 타임코드가 같은 시간축인지 검사하지 않는다.
- `evaluation/gold/manifest.json`은 정답이 없는 골격이다. 독립 골드 정답·블라인드 인적 평가·P3/P4 무작위 감사가 없어 품질 개선 또는 우선순위 모델의 재현율을 입증할 수 없다.
- 현재 워크스페이스에는 `final` 패키지가 없고, 작품별 번역 큐 보고서의 `final_promotion_allowed`도 모두 `false`다.
- 오디오 클립, ASR 후보, 캡처 인덱스, 번역 큐, 의미 프레임은 개별 파일로 존재하지만 한 검수 화면이나 단일 탐색 구조로 연결되어 있지 않다.
- 입력 해시와 번역 모델명은 남기지만, 번역 실행의 프롬프트/지시 버전, 실행 세션, 결정 결과 해시를 하나로 묶은 재현 기록은 없다.
- 승인형 용어집·번역 메모리가 없어서 작품 안팎의 인명, 호칭, 고정 표현, 수위 표현의 일관성을 체계적으로 검토하기 어렵다.
- Sol을 이용한 독립 반증·재검토 경로는 구현되어 있지 않다.

## 공통 원칙

1. 실제 원음·영상, 일본어 원문·문맥, ASR, 화면·캡처, 기존 한국어 후보의 권위 순서를 보존한다.
2. 모델의 출력은 근거가 아니라 검수 대상인 번역 후보다. 모델 간 불일치는 자동 해결하지 않고 검토를 요청한다.
3. 단계마다 산출물의 증거 수준을 명시한다. `draft`, `text-crosschecked`, `audio-asr-crosschecked`, `audio-human-verified`, `evaluation-validated`, `final`을 혼용하지 않는다.
4. 원본 입력·기존 결과·`vendor/` 보존 영역은 덮어쓰지 않는다. 모든 신규 결과는 버전과 입력 해시를 가진다.
5. 품질 지표는 잠긴 평가 세트 또는 블라인드 인적 판정이 있을 때만 보고한다.

## 단계별 계획

### 1. 시간축 검증 게이트

**현재 상태**: SRT 간 구조·겹침 정렬은 있으나 오디오/영상과 SRT 시간축의 적합성 검사는 없다.

**구현**: `inspect` 또는 `prepare-audio` 이전에 미디어 길이를 읽고, 구조 SRT의 마지막 타임코드와 비교하는 게이트를 둔다. 허용 오차, 검사 결과, 미디어 해시, 실패 사유를 매니페스트와 별도 시간축 보고서에 기록한다. 불일치가 임계값을 넘으면 ASR 클립 준비와 최종 승격을 중단한다.

**산출물**:

- `<title>.timeline-validation-vN.json`
- 매니페스트의 `timeline_validation` 상태와 원인
- 시간축 실패·보류 목록

**성공 기준**: P1/P2 클립을 만드는 모든 작품에 합격 또는 명시적 보류 상태가 있고, 합격한 클립의 끝 시각이 미디어 범위를 넘지 않는다.

**리스크와 의존성**: `ffprobe` 또는 동등한 미디어 메타데이터 도구가 필요하다. 서로 다른 편집본은 정당한 시간차를 가질 수 있으므로 자동 보정하지 않고 검수자가 오프셋을 승인해야 한다.

### 2. Terra 번역 프롬프트 아키텍처와 반복 템플릿

**현재 상태**: `gpt-5.6-terra`는 공식 의미번역 경로의 단일 허용 모델로 고정되어 있고, 번역 큐·결정·적용 보고서에 모델명이 기록된다. 반면 작품·장면·재검토에 반복 적용할 최소 프롬프트 템플릿, 템플릿 버전, 대표 실패 사례의 시험 규격은 없다. 이 단계는 Terra 호출기를 새로 만드는 작업이 아니다.

**구현**: `prompt-architect` 방식으로 짧고 버전 관리되는 Terra 번역 템플릿을 설계한다. 프롬프트 본문은 실행 설정과 분리하고, 모델 식별자는 기존 고정값 `gpt-5.6-terra`를 사용한다. 템플릿은 다음 최소 구성을 가진다.

- 목표: 구조를 보존한 원문 충실본과 의미 불변의 감상용 자연본을 각각 작성한다.
- 입력과 근거 우선순위: 직접 확인한 원음·영상, 일본어 원문·문맥, ASR 공통 핵심, 캡처/타임스탬프, 기존 한국어 후보 순서를 명시한다.
- 출력 분리: 블록별 `source_faithful_korean`, `viewer_natural_korean`, `translation_method`, `translation_model`, `confidence`, `evidence_refs`, `uncertain_slots`, `review_note`를 결정 JSONL 형식으로 요구한다.
- 제약과 금지: 질문·부정·허용·거절·화자·행동·대상·위치·시제·강도를 보존하고, 화면에만 보이는 행동·신체 부위·감정·관계나 원문에 없는 내용을 추가하지 않는다. 기존 한국어 후보의 단순 복사도 금지한다.
- 검증·중단 규칙: 불충분한 근거, 시간축 충돌, 필수 입력 누락, 상충하는 의미 슬롯은 번역을 창작하지 않고 `unresolved`/검토 사유로 남긴다. 프롬프트는 직접 원음 청취나 사람의 의미 검증을 대체하지 않는다.
- 테스트 사례: 정상 입력, 원문/ASR 일부 누락, 근거 충돌, 파일 또는 오디오 누락의 네 유형을 고정 사례로 둔다.

**산출물**:

- `prompts/` 아래의 Terra 번역 템플릿과 입력 계약
- 템플릿 버전·해시·적용 범위를 담은 프롬프트 매니페스트
- 대표 시험 입력과 기대되는 보류/출력 검증표

**성공 기준**: 템플릿이 실제 결정 JSONL 스키마와 충돌하지 않고, 네 유형의 시험에서 근거 없는 보완이나 최종 상태 과장을 하지 않는다. 프롬프트 변경은 이전 템플릿과 같은 locked-test를 통과한 뒤에만 기본값이 된다.

**리스크와 의존성**: 프롬프트가 길어질수록 품질이 자동 개선되지는 않는다. 1단계의 시간축 상태, 3단계의 평가 기준, 현재의 Terra 모델 고정·결정 스키마가 의존성이다. 실제 GPT/Codex 호출기 신설과 외부 전송은 이 단계의 범위가 아니다.

### 3. 정답 세트와 품질 평가 기반

**현재 상태**: 골드 디렉터리의 구조만 있고 정답·블라인드 평가·P3/P4 감사 표본은 없다.

**구현**: 직접 청취 가능한 장면을 작품별로 선정하여 일본어 전사, 의미 프레임, 허용 한국어 범위, 금지 해석, 오류 유형과 심각도를 사람 검수로 확정한다. `locked-test`는 번역 프롬프트·용어집·모델 비교 개발에 쓰지 않는다. Terra 번역안의 평가는 원문 충실본과 자연본을 가린 블라인드 패키지로 수행한다.

**산출물**:

- `evaluation/gold/{train,development,locked-test}`의 장면 기록
- 블라인드 검수 패키지와 평가 요약
- 오류 유형별 판정 원장(MQM 연계)

**성공 기준**: 각 평가 레코드에 직접 청취 여부, 근거, 허용 범위, 판정자가 있고 locked-test가 개발 입력과 분리된다. 점수는 표본 수·범위·불확실성과 함께만 보고한다.

**리스크와 의존성**: 일본어 청취 검수자와 이견 조정 절차가 필요하다. 작은 표본의 수치를 전체 작품 성능으로 일반화하지 않는다.

### 4. 근거 기반 검수 경험

**현재 상태**: `review-context.jsonl`, ASR CSV, 장면 클립, 번역 큐, 캡처 인덱스가 있으나 검수자는 여러 파일을 오가야 한다.

**구현**: 장면/블록별 검수 패킷 또는 내부 검수 화면을 만든다. 한 화면에서 시간코드, 일본어 원문과 앞뒤 문맥, 오디오 재생, ASR 후보와 독립성 표기, 기존 한국어 후보, 캡처 상태, 두 한국어안, 의미 슬롯, 근거·불확실성·결정 상태를 본다. 화면은 의미를 추론하지 않고 검수자의 결정 JSONL 작성을 돕는다.

**산출물**:

- 버전이 있는 HTML 또는 로컬 검수 패킷
- 검수자 행동을 결정 JSONL·근거 ID로 되돌리는 링크
- 미결·충돌·직접 청취 필요 필터

**성공 기준**: P1/P2 한 장면을 검수하는 데 필요한 근거가 하나의 패킷에서 열리고, 승인·보류·반려 결정이 원본 근거 ID와 연결된다.

**리스크와 의존성**: 민감한 영상·음성의 로컬 보관과 접근 통제가 필요하다. 캡처 파일의 존재를 의미 해석으로 표시해서는 안 된다.

### 5. 능동 검수와 검수 예산 배분

**현재 상태**: P1/P2는 휴리스틱 또는 제공 위험 모델의 우선순위이며, P3/P4 감사 정답이 없어 실제 오류 포착률을 알 수 없다.

**구현**: P1/P2 전수 검토와 P3/P4 무작위 감사 표본을 같은 오류 원장으로 기록한다. 그 결과로 오류 유형별 recall, 검수 예산 5/10/20%에서의 recall·precision, critical 오류 포착률, false negative를 계산한다. 이후에만 위험 점수나 검수 순서를 조정한다.

**산출물**:

- 시드와 추출 규칙이 있는 무작위 감사 패킷
- 작품별·오류 유형별 검수 커버리지 보고서
- 우선순위 변경 전후의 블라인드 비교 결과

**성공 기준**: 우선순위 규칙이 ‘그럴듯함’이 아니라 잠긴 표본에서의 오류 포착률과 검수 비용으로 설명된다.

**리스크와 의존성**: 현 위험 점수는 보정된 확률이 아니므로 임계값을 정답 판정 기준으로 사용하면 안 된다. 2단계의 판정 데이터가 선행돼야 한다.

### 6. 승인형 용어집과 번역 메모리

**현재 상태**: 블록별 결정은 있으나, 승인된 일본어 표현·읽기·호칭·한국어 대응·금지 표현을 관리하는 계약이 없다. 공용 오류 기억을 자동 편입하지 않는 현재 원칙은 유지해야 한다.

**구현**: 사람 승인 전용 용어집을 도입한다. 항목에는 일본어 표기/읽기, 문맥·작품 범위, 승인 한국어, 허용 변형, 금지 표현, 의미·수위 주의, 근거 ID, 승인자와 버전을 둔다. 번역 큐는 후보 항목을 제시할 수 있지만 자동 치환하지 않는다.

**산출물**:

- 버전 관리되는 `glossary`/translation-memory 레코드
- 결정 JSONL의 `terminology_refs`
- 용어 충돌·미승인 재사용 검토 큐

**성공 기준**: 동일 표현의 재사용은 근거·범위·승인 상태를 함께 보여 주고, 다른 장르/작품의 표현이 무단으로 전파되지 않는다.

**리스크와 의존성**: 고유명사·문체·성적 표현은 문맥 의존적이다. 전역 자동 치환은 금지하고 2단계의 승인·평가 기준을 적용한다.

### 7. 장면·근거 그래프

**현재 상태**: semantic frame, hypothesis ledger, ASR source family, alignment evidence는 개별 형식 검증이 가능하지만 하나의 탐색 가능한 관계 구조는 없다.

**구현**: `scene`, `block`, `evidence`, `decision`, `hypothesis`, `evaluation`을 안정적인 ID로 연결하는 JSONL 그래프를 만든다. 각 간선에는 근거 종류, 독립 source family, 생성 시각, 검수 상태를 기록한다. 충돌 화면은 다수결 대신 상충하는 슬롯과 필요한 다음 근거를 표시한다.

**산출물**:

- `<title>.evidence-graph-vN.jsonl`
- 블록별 근거 계보와 충돌 목록
- 패키징 전 고아 결정·끊긴 근거 참조 검사

**성공 기준**: 임의의 최종 자막 블록에서 일본어 원문, 사용한 ASR/문맥, 결정자, 미해결 가설, 평가 판정까지 역추적할 수 있다.

**리스크와 의존성**: 기존 산출물에 안정 ID가 없거나 부족한 경우가 있어 마이그레이션 규칙이 필요하다. 3단계 검수 패킷과 5단계 용어 참조가 주요 입력이다.

### 8. 선택적 Sol 반증 실험

**현재 상태**: 의미번역의 공식 생성 경로는 `gpt-5.6-terra`로 고정되어 있고, Sol 재검토 경로는 없다.

**구현**: Sol은 Terra의 대체 생성기나 자동 심판으로 쓰지 않는다. 직접 청취가 필요하거나 P1/P2·의미 슬롯 충돌이 있는 구간에서 Terra 결정을 반증할 후보를 제시하는 독립 검토자로만 제한한다. Sol 결과는 별도 `reviewer_model`, `review_reason`, `disagreement_type`으로 기록하고, 최종 채택은 사람·직접 근거가 결정한다.

**산출물**:

- 제한된 재검토 패킷과 Sol 의견 레코드
- Terra 단독 대비 오류 발견·불필요 경보·검수 시간 비교
- 외부 전송·비용·승인 로그

**성공 기준**: locked-test를 보지 않은 조건에서 Sol이 실제 critical 오류 발견 또는 검수 효율에 기여했는지 블라인드 평가로 확인한다. 기여가 없으면 기본 흐름에 넣지 않는다.

**리스크와 의존성**: 사용자 승인, 모델 접근·비용 정책, 3단계의 locked-test, 4단계의 검수 기록 형식이 필요하다. Sol의 다수결·자기확신을 사실 판정으로 사용하지 않는다.

## 측정 지표

아래 지표는 2단계의 정답 또는 블라인드 판정이 마련된 뒤에만 계산한다.

- 오류 유형별 accuracy/MQM 심각도 분포와 critical 오류 잔존 수
- 검수 예산 5/10/20%에서 recall·precision 및 critical-error recall
- P1/P2와 P3/P4 감사의 false negative, 커버리지, 검수 시간
- 원문 충실본과 자연본의 의미 차이·가독성 경고·중복 경고
- 직접 청취 검증률, 미결 슬롯 수, 근거가 없는 결정 수
- 용어집 일관성 위반 수와 승인 전 재사용 시도 수
- 실행 재현성: 입력·프롬프트·결정·산출물 해시가 연결된 번역 실행 비율
- Terra 단독과 선택적 Sol 반증의 오류 발견률·오경보·추가 검수 비용

## 출시 및 검증 순서

1. 시간축 게이트를 먼저 적용해 잘못된 오디오·자막 연결을 차단한다.
2. Terra 프롬프트 템플릿과 시험 사례를 고정해 같은 입력 계약으로 결정 기록을 만든다.
3. 직접 청취 정답과 locked-test를 만들고, 평가 기준을 먼저 고정한다.
4. 근거 기반 검수 패킷을 구축해 판정·근거·보류를 구조화한다.
5. P3/P4 감사 데이터를 수집한 뒤 능동 검수의 우선순위를 평가한다.
6. 승인형 용어집과 근거 그래프를 도입해 결정의 재사용·감사를 가능하게 한다.
7. Terra 기본 경로가 측정 가능한 기준선을 만든 뒤에만 Sol 반증 실험을 별도 플래그로 실시한다.
8. 각 단계는 새 산출물의 해시, QA, 롤백 가능한 버전, 실패·보류 사유를 남긴 뒤 다음 단계로 진행한다.

## 결정이 필요한 항목

- 시간축 게이트의 허용 오차와, 편집본 차이를 사람이 승인하는 절차
- 직접 청취·이견 조정을 맡을 역할과 접근 권한
- 평가에서 허용할 한국어 변형의 범위와 critical 오류 정의
- 민감한 음성·영상·캡처를 검수 패킷에 포함할 때의 저장·접근·전송 정책
- 용어집의 승인권자, 작품 간 재사용 범위, 폐기·수정 이력 규칙
- Sol 반증 실험의 모델 사용 승인, 비용 한도, 외부 전송 허용 여부, 실행 조건
- `final` 승격을 위한 최소 평가 표본과 승인 책임자

## 외부 증거 없는 폐쇄형 자동 검증

`run-closed-world`는 사람 정답이나 외부 서비스를 사용할 수 없는 경우를 위한 별도 경로다. 모든 구조 블록을 `accepted` 또는 `abstained`로 판정하고 구조 고정 미리보기, 의미 격자, 미확정 목록, 품질 주장 증명과 결정적 실행 매니페스트를 만든다.

이 경로가 보장하는 범위는 구조·재현성·명시적 의미 슬롯 규칙·미확정 보류다. 관측되지 않은 사람 정답과의 동일성은 `unidentifiable`로 기록한다. `closed-world-validated`는 사람 검증 상태나 `final`로 자동 승격되지 않는다.

## 완료 판단

이 계획의 완료는 기능 수가 아니라 증거로 판단한다. 시간축이 검증되고, 잠긴 평가 세트에서 검수 효율과 오류 포착률을 비교할 수 있으며, 최종 자막의 각 중요한 결정이 근거와 검수 상태까지 역추적될 때에만 개선 효과를 주장한다.
